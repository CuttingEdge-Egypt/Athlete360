The "Payment declined" error from Paymob, especially with the message "The payment session ends after 3 unsuccessful trials," points to a problem with the creation of the payment session itself. Based on the provided code, the most likely cause is an incorrect data type for the amount_cents field sent to Paymob's API.
Root Cause Analysis
The Paymob payment flow requires three steps: authenticating, creating an order, and finally, generating a payment key for the checkout page. The error originates in the third step, "Generate payment key."
Paymob's API strictly requires that the amount_cents field be an integer. While your backend code in routes.ts correctly converts the package price to cents by multiplying by 100, the resulting value might be a float (e.g., 1500.0) instead of an integer (1500).
In the paymobService.ts file, the payload for generating the payment key does not enforce this integer requirement for the amount, although it correctly does so for order_id and integration_id.
Problematic Code in paymobService.ts:
code
TypeScript
const paymentKeyPayload = {
  auth_token: token,
  amount_cents: paymentData.amount, // This could be a float, causing the issue.
  expiration: 3600,
  order_id: parseInt(orderData.id), // Correctly parsed to integer
  billing_data: {
    // ...
  },
  currency: paymentData.currency || 'EGP',
  integration_id: parseInt(integrationId!) // Correctly parsed to integer
};
When Paymob receives a non-integer amount_cents, it fails to properly initialize the checkout session. This leads to a broken payment page where the order amount is missing, and any attempt to complete the transaction is immediately declined.
Recommended Solution
To fix this issue, you must ensure the amount_cents value is explicitly converted to an integer before it's sent to Paymob.
Apply the following fix to the paymentKeyPayload object in the createPaymentIntention function within paymobService.ts:
code
TypeScript
// In paymobService.ts

const paymentKeyPayload = {
  auth_token: token,
  // FIX: Ensure amount_cents is always an integer
  amount_cents: parseInt(String(paymentData.amount), 10),
  expiration: 3600,
  order_id: parseInt(orderData.id),
  billing_data: {
    // ...
  },
  currency: paymentData.currency || 'EGP',
  integration_id: parseInt(integrationId!)
};
By wrapping paymentData.amount with parseInt(String(...), 10), you guarantee that the value sent to Paymob is always in the correct integer format, which will resolve the payment decline error and allow the checkout process to function correctly.
