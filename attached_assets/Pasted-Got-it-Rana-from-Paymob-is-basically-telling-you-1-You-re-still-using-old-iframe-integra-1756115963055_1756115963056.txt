---

### 🔹 2. Understand the New Flow (Flash / Unified Checkout)

Instead of multiple steps with iframe tokens, now you only:

1. **Call the “Create Intention” API**
   → This will define the amount, currency, integration ID, and payment method.
2. **Redirect user to Paymob’s checkout page (Flash)**
   → Paymob handles OTP, 3DS, cards, wallets, etc. automatically.
3. **Receive a callback/webhook from Paymob**
   → Confirms payment success/failure on your backend.

Docs: [Create Intention API](https://developers.paymob.com/egypt/api-reference-guide/create-intention-payment-api)

---

### 🔹 3. Backend Setup (Server Side)

* Create an API route on your backend (e.g., `/create-payment-intent`)
* From your backend, call Paymob’s `POST /v2/intention/` API:

  ```json
  {
    "amount": 10000,        // in cents (e.g. 100.00 EGP)
    "currency": "EGP",
    "payment_methods": [your_integration_id],
    "merchant_order_id": "unique_order_id_123",
    "items": [
      {
        "name": "Product Name",
        "amount": 10000,
        "quantity": 1
      }
    ]
  }
  ```
* Paymob will return a `redirect_url`.

---

### 🔹 4. Frontend Setup

* From your frontend checkout flow, when the user confirms the order:

  * Call your backend `/create-payment-intent`
  * Get the **`redirect_url`** from Paymob’s response
  * Redirect the user there
  * Example:

    ```js
    window.location.href = response.redirect_url;
    ```

---

### 🔹 5. Handle Webhooks (Very Important ✅)

* Configure a webhook endpoint in your backend (e.g., `/payment/callback`)
* In Paymob dashboard → add your webhook URL
* Verify webhook with **HMAC secret** (they mentioned it in the email)
* Update your database:

  * Mark order as **Paid** if success
  * Or handle **Failed/Cancelled** payments
